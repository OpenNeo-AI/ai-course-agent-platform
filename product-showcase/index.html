Value Proposition

教育咨询的真正战场

当课程产品越来越复杂，咨询竞争进入精准运营期。核心命题不再是资料有多少，而是每一次回答能否让用户立刻做出正确决策。

AI 课程顾问不是一套简单的问答机器人，而是教育机构的数字课程顾问——帮运营者看清知识边界在哪里、费用该如何计算、用户该推荐什么班型。

Engineering Philosophy

知识即数据，规则即记录

面向专家评审的建设思路：以 Palantir Foundry 本体范式为核心，将课程领域的业务实体与规则建模为类型化对象，通过确定性引擎执行计算，从根本上消除大模型在垂直领域的数字幻觉。

AI 课程顾问的核心设计原则：知识即数据，规则即记录，配置即文件。所有业务数值均存于库内规则对象，引擎代码中不含任何价格、日期、人数的字面量。

Domain Architecture

知识域是唯一的边界单位

摒弃素材 A/B/C 的硬分类，采用知识域 -> 知识库 -> 文档三级结构。智能体通过 agents.yaml 声明对接的知识域，范围外内容在工具层不可见。

Hierarchy

三级知识结构

实体 / 规则 / 知识块经 文档 -> 知识库 -> 知识域 链路归属，无 material 列。资料分类的本质是知识域隔离。

  • 知识域 Domain：语义边界单元，可自建扩展
  • 知识库 KB：文档集合与对应的本体实体、检索索引
  • 文档 Document：原始文件，用于对象溯源

学生通道无法检索教师域价格，教师通道无法访问学生域内容

DOMAIN

Retrieval Pipeline

多路混合检索

原始问题先经 LLM 结构化改写，三路并行召回后经 RRF 融合与 LLM 重排。价格、日期等精确事实直接由本体命中，不经过 LLM 改写。

  • 向量语义召回：doubao-embedding-vision 2048 维 + sqlite-vec
  • FTS5 关键词召回：trigram 中文分词
  • 本体精确匹配：产品 / 营期 / 规则结构化直取
  • RRF + LLM Rerank：Top-K 生成，自动标注引用

Query Rewrite → Vec + FTS + Ontology → RRF → Rerank → Generate + Citation

RETRIEVAL

三路并行召回与重排管线

Tech Stack

单一 SQLite，单一 FastAPI 服务

本体、向量索引、全文检索、会话与消息全部存储在单一 SQLite 文件。FastAPI 同时提供 REST + SSE、三个 MCP streamable HTTP 端点、静态前端。

核心工具一份实现三处复用：Agent 会话循环、MCP server、REST API 调用的是同一份 tools.py。

后端

Python · FastAPI · uvicorn · sqlite-vec · FTS5 · MCP Python SDK

前端

大模型

火山方舟豆包：对话 / function calling / embedding / 重排评分

部署

nginx → uvicorn · systemd 守护 · 单文件备份
