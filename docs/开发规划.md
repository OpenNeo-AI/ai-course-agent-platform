# OPC 参赛项目整体规划：AI课程顾问Agent平台

## Context

参加「OPC接单吧·首届软件与智能体开发大赛」，赛题为 **AI课程顾问Agent**（规格见 `doc/统一赛题.docx`）。知识素材：`doc/学生个人课程资料.docx`（学生夏令营）、`doc/教师个人培训资料.docx`（教师培训 L1-L3）、`doc/平台与企业服务资料.docx`（平台/会员服务）。

**当前状态**：考题必做已全部实现并通过 25 组官方验收用例；并在此基础上演进为**智能体运营平台**——以知识域为唯一边界、规则全部对象化入库、围绕智能体上下游构建运营/质控/人机协作能力。已公网部署（`https://edu-demo.openneo.ai/`）。

**用户愿景**：portal 统一管理知识文档/LLM 参数/渠道令牌；后端 = 向量库 + SQLite + ontology 结构化知识；问答核心封装为 **MCP server**（渠道令牌鉴权）；前端 = 学生/教师/平台三通道 H5 + 管理工作台；MCP 同时封装为 **OpenClaw 兼容 skill**（WorkBuddy 兼容）；运营分析调用 LLM；整体 AI 原生，MCP/skill 优先。

**核心约束（已并入设计）**：
1. **Ontology 文档驱动、可扩展、可维护、前端可查看**——ontology 从知识文档结构化抽取、随文档扩展、portal 可查看/确认/编辑，是一等数据资产。
2. **问答多路检索**——原始 query 先结构化改写，三路召回（向量/FTS5/ontology 精确匹配）后统一重排（rerank）再生成。
3. **知识域化（去素材硬编码）**——知识以「知识域」为唯一边界单位（而非素材 A/B/C 硬分类）；智能体在 `agents.yaml` 配置对接的知识域，范围外内容不参与其检索/推荐/计算。
4. **规则全部对象化**——早鸟/团报/叠加/退费/前置/**推荐策略**均建模为库内规则记录，通用解释引擎执行，**代码零业务数值**。
5. **围绕智能体上下游、不做课程业务系统**——运营/质控/人机协作能力围绕智能体构建，**不做**课程 CRUD/报名管理/支付/学员档案。

**已确认选型**：Python 全栈（FastAPI + MCP Python SDK，前端 React+Vite）；向量存储 = sqlite-vec + FTS5（SQLite 单文件混合检索）；LLM = 火山方舟·豆包（OpenAI 兼容接口，chat + embedding + rerank，密钥走环境变量，不入库）。

**核心设计原则**
1. **知识域为唯一边界（去素材硬编码）**：知识域 -> 知识库 -> 文档三级结构；实体/规则/知识块经 文档->知识库->知识域 链路归属，无 material 列。智能体按对接知识域隔离（学生通道无法访问教师域）。知识域可自建可扩展；平台域资料缺失时如实回答"无法确认"。
2. **规则全部对象化、通用解释**：早鸟/团报/叠加/退费/前置/**推荐策略**均建模为库内规则记录（参数即数据），通用解释引擎执行，代码零业务数值；推荐策略为声明式规则（needs/match/日期来源/限额），引擎通用解释。
3. **多路检索 + 改写 + 重排**：query 结构化改写 → 三路召回（向量/FTS5/ontology 精确匹配）→ RRF 融合 → rerank → top-k；ontology 命中精确事实（价格/日期）直取结构化数据，杜绝幻觉。
4. **一份工具实现，三种暴露**：core 工具 → 内部 Agent 循环 / MCP server / REST 三处复用；工具按智能体能力装配（留资转人工可开关）。
5. **围绕智能体的运营平台（非课程业务系统）**：数据分析、对话质检、人工跟进（留资转人工）、渠道令牌均为智能体运营能力，按智能体可配置；不做课程/报名/支付/学员档案。

## 数据模型（SQLite 单文件 data/app.db）

**知识层（文档驱动，portal 可查看）**
- `domains(id, code, name, description)` — 知识域，唯一边界单位，可自建。
- `kbs(id, code, name, domain_id)` — 知识库，隶属知识域。
- `documents(id, kb_id, filename, title, status)` — 文档，隶属知识库。
- `entities(id, type, name, attrs_json, doc_id, chapter, status)` — type ∈ product/period/location/person/fee_item/…；经 doc_id 归属。
- `relations(src_id, rel, dst_id, doc_id)` + `edges(src_node, dst_node, rel, origin, domain_id)` — 抽取链接 + 派生/人工链接（三分来源 extracted/derived/manual）。
- `rules(id, kind, scope_json, params_json, doc_id, status)` — kind ∈ early_bird/group_discount/stack_policy/fee_formula/refund/prerequisite/**recommend**；全部规则记录，通用引擎解释，代码零数值。
- `knowledge_chunks / chunks_vec(vec0) / chunks_fts(FTS5)` — 每块存 kb_id + 文档名 + 章节（引用溯源）。

**会话与运营层**
- `sessions(state_json: identity/domain/constraints/current_product) + messages(含 tool_calls)` — 多轮上下文与运营数据源。
- `quality_checks(session_id, agent_role, score, accuracy/compliance/experience, issues_json, comment)` — 对话质检评分。
- `leads(session_id, agent_role, name, phone, intent, status, follow_note)` — 报名意向留资工单（留资转人工，非报名管理）。
- `channel_tokens(name, token, disabled, last_used_at)` — 渠道 MCP 接入令牌。
- `insights(scope, content)` — LLM 运营洞察报告。

**Ontology 构建管线**：`ingest/extract.py` 用 LLM function-call 按 Schema 从章节抽取候选实体/关系/规则 → 入库 status=extracted → portal 确认/修正；`tests/test_ontology_facts.py` 对各知识域已知事实做回归断言锁死。

## MCP 工具设计（核心契约，内部/外部共用）

| 工具 | 输入 | 行为 |
|------|------|------|
| `get_welcome` | — | 固定模板：服务范围 + 入口引导 |
| `list_products` | — | 枚举智能体知识域内真实班型 |
| `recommend_products` | city?, dates?, mode?, level?, days_off?, goal? | 引擎按库内推荐策略确定性筛选 → LLM 生成逐条对应约束的理由 |
| `ask_knowledge` | question, product_hint? | 结构化改写 → 三路召回 → RRF → rerank → LLM 生成，末尾引用卡片 |
| `calculate_fee` | product_name, payment_date, group_count?, boarding? | 规则引擎执行库内规则，**纯确定性**，返回逐项拆解 |
| `get_enrollment_info` | product_name? | 报名/退费/前置（来自 ontology）；无报名方式 → "请联系人工课程顾问" |
| `capture_lead` | name, phone, intent, note | 留资转人工（需启用 lead_capture 能力）；不提供任何联系方式 |

**渠道令牌鉴权**：MCP 端点经 `Authorization: Bearer ak_…` 校验渠道令牌；系统存在有效令牌时强制校验，无令牌时开放兼容；portal「系统设置→渠道令牌」签发/禁用/复制配置。

H5 会话控制（取消/重来/查看全部课程）由 agent 循环处理：重置清空 state，重置后不引用旧班型。输入校验：空→提示重输；>500字→提示精简；特殊符号不崩溃；LLM 异常→"请稍后重试"；无关问题→说明边界。

## 验证

- **事实回归**：`pytest tests/test_ontology_facts.py` 20/20，覆盖各知识域价格/日期/优惠组合/退费/前置/推荐筛选断言（经规则引擎执行）。
- **验收回归**：`python tests/run_acceptance.py` 25 组（事实8/边界4/推荐5/多轮3/异常5）24-25/25。
- **检索质量**：典型 query 断言改写结构、三路召回命中、rerank top-1 相关；ontology 精确问题直取结构化事实。
- **MCP 契约**：initialize → tools/list → tools/call 全链路；渠道令牌鉴权（无令牌开放/有效 200/无效 401）。
- **端到端**：公网链接 + 手机扫码走 /s /t /c 完整流程；portal 全流程（知识域/本体/智能体/分析/质检/工单/渠道令牌）。
- **红线自查**：无密钥入库、无真实联系方式、课程答案均经检索生成（模板仅限欢迎/菜单/重置/错误）。

## 风险与注意

- 平台白皮书资料若未入库，平台会员/企业合作问题一律"无法确认"，不编造；资料补充后 portal 上传即可，无需改代码。
- 演示与测试记录中不得出现 .env/wink.pem/真实密钥。
- 服务器链接保活（systemd 自动拉起 + 健康检查）。
- 对话质检为 LLM 评分，供质量管理参考，受模型判断影响。
