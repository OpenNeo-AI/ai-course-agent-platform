# 系统架构说明 -- AI 教育顾问 SaaS 平台

> 交付物（A级测试单 L3）：说明 RAG 链路设计、Agent Skill 架构、数据库设计、支付流程、运营工作台、部署方案。
> 对应评分维度：RAG 25% / Agent Skill 25% / 商业化支付 15% / Admin 后台 20% / AI 对话 10% / 部署 5%。

## 一、总体架构

系统为「智能体运营平台」向多租户 SaaS 的扩展。整体为单体服务（FastAPI + SQLite + React 单页应用），
在原有「知识域智能体」能力之上叠加 SaaS 层：多租户、套餐订阅、支付、租户工作台与平台经营工作台。
单进程 uvicorn 同时伺服 API / SSE 对话 / MCP / 静态前端，无 nginx 前置也可独立运行（容器化路径）。

```
浏览器(React SPA) ──HTTP/SSE──▶ FastAPI ──▶ SQLite(data/app.db, WAL)
  /s /t /c 官方三通道            ├─ /api/auth/*        手机验证码/密码认证(JWT)
  /b/<agent_slug> 租户智能体     ├─ /api/session /chat 会话与 SSE 流式对话
  /portal 统一工作台             ├─ /api/portal/*      管理工作台(知识域/本体/配置/会话/运营/订单/渠道)
  /pricing /login /register     ├─ /api/tenant/*      租户(智能体/机构信息/文档/统计)
  /admin 租户管理                ├─ /api/billing/*     套餐/订单/支付/回调
                                 ├─ /api/skills        Agent Skill 自描述元数据(供评审)
                                 ├─ /api/tool          通用工具 REST 入口(按角色收敛作用域)
                                 └─ /mcp /mcp/student /mcp/teacher   MCP(官方三智能体,Bearer 渠道令牌)
```

**一份工具，三种暴露**：六个基础工具（`get_welcome` / `list_products` / `recommend_products` /
`ask_knowledge` / `calculate_fee` / `get_enrollment_info` + `set_session_context`）及两个 SaaS
Agent Skill（`get_course_detail`、`recommend_course_type`）、留资工具 `capture_lead`，统一在
`app/core/tools.py` 实现，同时服务会话循环、MCP server 与 REST，取数与计算均以知识域为范围。

**配置即文件、热加载**：`data/config/llm.yaml`、`prompts/*.md`、`ontology_schema.yaml`、
`agents.yaml` 按 mtime 热加载；`app/core/config.py` 统一读取，环境变量（`.env`）优先于 yaml。
`data/` 整体 gitignored，首部署由脚本初始化。

## 二、RAG 链路设计

1. **摄入**：文档（.pdf/.docx/.doc/.txt，`app/core/ingest/parse.py`）上传 -> 后台异步线程解析
   -> 按章节切块（`CHUNK_SIZE`/`CHUNK_OVERLAP` 可配）-> Embedding（火山方舟）写入
   `knowledge_chunks` + FTS5(trigram) + vec0 向量表。
   - 后台摄入走 `threading.Thread` + `get_db_autocommit()`，每条语句即时提交，不跨网络调用持写锁，
     不影响其他接口；同步执行会 `database is locked`。
   - 同名重传幂等重建，FTS/vec0 索引同步刷新；vec0 表在首次向量化拿到维度后延迟创建。
2. **召回**（`app/core/retrieval/search.py`）：query 经 LLM 结构化改写（子句/关键词/意图）->
   三路并行召回（向量 KNN / FTS5 关键词 / 本体精确事实）-> RRF 融合 -> rerank 重排 -> top-k。
   - 知识域引用范围由调用方注入（`domain_ids` 知识域 + `kb_ids` 知识库）：范围外的知识块不参与召回。
   - 本体精确命中（价格/日期/营期）直取结构化事实卡片，杜绝数字幻觉；sqlite-vec 不可用时向量路降级为空，
     主流程仍可由 FTS5 + 本体支撑。
3. **生成与引用**：`answer.md` 提示词仅依据检索结果作答；结构化引用
   `{source: 《文档名》, chapter: 章节, excerpt}` 随 `done` 事件下发，前端以卡片渲染。
   `loop.py` 有兜底补引用逻辑（勿删）。库外问题答「该问题不在我的知识范围内」。

## 三、Agent Skill 架构

**工具集**（OpenAI function-calling JSON Schema，`app/core/tools.py`）：六个基础工具覆盖欢迎/列表/
推荐/问答/计费/报名信息；两个 SaaS Agent Skill 供评审查验：
- `get_course_detail`（参数 `product_name`，返回 时间/地点/费用/师资/大纲 + 适用优惠规则 + 引用）
- `recommend_course_type`（参数 `city`、`time_preference`，返回 1-2 个班型 + 理由 + 引用）

`GET /api/skills` 输出 `SKILLS_META` 自描述元数据（含参数 JSON Schema 与返回字段说明），供评审按
「Agent Skill 架构」维度校验。`GET /api/tool`（{name, args, role}）为通用 REST 入口，role 决定作用域。

**会话循环**（`app/agent/loop.py`）：function calling + 会话状态持久化（`sessions.state_json`）。
租户会话按智能体 `config_json` 的能力位动态装配工具：`lead_capture` 开启则纳入 `capture_lead` 留资工具，
`tenant_bot` 开启则追加两个 Agent Skill；官方三通道工具集保持不变（验收零漂移）。

**降级策略**：缺参返回 `need` 追问、实体不存在返回 `available` 列表、模型异常固定文案「稍后重试」，
Skill 调用失败降级为 LLM 直答或提示补充参数，不报错终止。`MAX_TOOL_ROUNDS` 限制工具循环轮数。

## 四、数据库设计

SQLite 单文件 `server/data/app.db`（WAL）。SCHEMA 常量集中在 `app/core/db.py`，启动 `get_db()` 连接时
执行建表与有序迁移（`_migrate_saas` / `_migrate_saas_plans` / `_seed_saas` / `_migrate_drop_materials`）。

**业务本体**（三层知识 + 规则对象化）：
- `domains -> kbs -> documents -> knowledge_chunks`（FTS5/vec0 索引）；身份体系以知识域为唯一单位，无素材 A/B/C 概念。
- `entities` / `relations` / `edges`（统一链接表，抽取产出的实体关系存 relations，派生/人工链接存 edges，
  链接三分来源 extracted/derived/manual）/ `rules`（早鸟/团报/叠加/退费/前置/推荐策略全部对象化，由
  `ontology/engine.py` 通用解释器执行，**代码里零业务数值**）/ `actions_log`（本体操作审计）。

**会话与运营**：`sessions`（含 `state_json` 会话状态）/ `messages` / `insights`（LLM 运营洞察报告）/
`quality_checks`（对话质检评分：总分/准确性/规范性/体验 + 红线问题）/ `leads`（报名意向线索工单：
留资转线索，状态 pending/followed/converted/invalid）/ `channel_tokens`（MCP 接入的 Bearer 渠道令牌）。

**SaaS 多租户层**（8 表）：
- `tenants`（机构 + `service_purpose` 服务宗旨 + `bot_config_json` 智能体设置）
- `users`（超管/租户管理员，手机号+密码，`pbkdf2_sha256` 哈希；`tenant_id=NULL` 为平台超管）
- `plans`（free/standard/flagship 三档 + `features_json` 功能位 + `agent_limit`）
- `subscriptions`（每租户一条，套餐与状态）、`usage_monthly`（月度对话计数，免费版按累计 10 次）
- `payment_orders`（`out_trade_no`/渠道/状态/`trade_no` 回填）
- `sms_codes`（手机验证码，5 分钟有效）、`tenant_agents`（每租户多智能体，独立 `slug` 前台链接与 `config_json`）

**作用域与隔离**：会话按 `agent_id` 绑定智能体，知识域按挂载列表过滤；跨租户查询先解析 tenant_id 再收敛
kb_ids（`portal._tenant_kb_ids` 须在 `with get_db()` 块内部调用，否则拿到已关闭连接）。

## 五、支付流程

渠道注册表 `payments.CHANNELS`（`app/core/payments.py`，`PaymentChannel` 基类）：
- **MockChannel**：演示环境模拟支付，确认即成功（明确标注不产生真实扣款，测试单允许）。
- **WechatNativeChannel**：微信 Native 扫码（V2 API，MD5 签名，XML），返回 `code_url` 前端扫码。
- **AlipayPageChannel**：支付宝电脑网站支付（`alipay.trade.page.pay`，RSA2 签名），返回 `pay_url` 跳转。

订单生命周期：`create_order`（生成商户单号，对渠道**严格校验、不静默回退**）-> `pay_success`（幂等置 paid）
/ `query_order`（前端 2s 轮询，主动向渠道查单）/ `pay_by_out_trade_no`（回调）。
渠道异步回调走 `/api/billing/callback/{alipay,wechat}`，验签后幂等置 paid -> 订阅升级、功能解锁。
密钥经 `.env` 注入（`WECHAT_*` / `ALIPAY_*` / `JWT_SECRET` / `ALIYUN_*` 短信），经 `_norm_pem` 处理字面 `\n`。

**订阅与门禁**：`tenancy.subscription_of` 校验订阅有效，`portal._require_feature(db, p, feature, label)`
按 `features_json` 布尔键校验（`agent_settings` 全档；`domains`/`rag_manage`/`ontology`/`skills` 为 standard+；
`agent_caps`/`sessions`/`leads`/`analytics` 为 flagship 独占）。新增受限功能加 feature key，不硬编码套餐 code 比较。
免费版配额用累计次数（`usage_total`）而非月度计数，超额在 `done` 事件回传 `quota_exceeded` / `subscription_required`。

## 六、运营工作台与数据看板

`Portal.tsx` 是**按身份自适应的单一工作台**：超管看到 tenants/plans/orders/board/system，租户看到
institution/agents/docs/ontology/sessions/leads/analytics/usage/sub，套餐不含的 tab 显示 `LockPanel` 引导升级。
后台 API 在 `app/api/portal.py`（49 个端点，`/api/portal` 前缀，`_principal` 从 JWT/portal token 解析身份）与
`app/api/saas.py`（`/api/*` 前缀，覆盖 auth/billing/tenant/skills/usage）。

**平台经营看板**（加分项 数据看板 +2）：`GET /api/portal/dashboard` 输出租户数/用户数/对话数总量 +
近 14 日会话趋势 + 租户对话排行；`GET /api/portal/analytics` 输出运营指标（概览/各智能体/趋势/高频问题/
未答问题/推荐班型分布/质检均分），超管看全量可按智能体筛选，租户收敛到本租户会话。
`GET|POST /api/portal/analytics/insight` 由 LLM 生成运营洞察报告（存 `insights` 表）。

**质检与线索**：`POST /api/portal/quality/{session_id}` 与 `/quality/batch` 对对话做 LLM 质检打分
（准确性/规范性/对话体验 + 红线问题，存 `quality_checks`）；对话中 `capture_lead` 工具留资写入 `leads`，
`GET /api/portal/leads` 提供跟进工单视图（状态流转 + 跟进备注）。

**MCP 渠道令牌**（`GET|POST|DELETE /api/portal/channels`）：分发给第三方 Agent/系统接入 MCP 的
`ak_` 前缀 Bearer 令牌。`main._ChannelAuthASGI` 包装三个 MCP 端点：系统存在有效（未禁用）令牌时要求携带
有效令牌，尚无任何令牌时保持开放（向后兼容）。令牌最后使用时间回写 `channel_tokens.last_used_at`。

## 七、部署方案

两条互不干扰的部署路径，均 15 分钟内可运行：

### 7.1 公网 systemd 部署（生产）
单机 nginx -> uvicorn/systemd（`deploy/opc-edu.service`），HTTPS Let's Encrypt。
`deploy/deploy.sh` 以 **tar-over-ssh 管道**同步代码（Windows git-bash 无 rsync），远端装依赖 ->
`systemctl restart opc-edu`。部署前必须构建前端（`web && npm run build`）并跑验收
（`tests/run_acceptance.py`），否则拒绝部署。远端 `.env` 在 `/opt/opc-edu/.env`，不随同步传输。

### 7.2 Docker Compose 一键部署（评审路径，加分项 +2）
多阶段构建（`docker/Dockerfile`：`node:22-alpine` 编译前端 -> `python:3.12-slim` 运行时），
`docker-compose.yml` 一键入口，无 nginx，单进程 uvicorn 伺服 API/SPA/MCP。

```bash
cp .env.example .env      # 至少填 VOLCANO_API_KEY
docker compose up -d      # -> http://localhost:7000,首启后台初始化 6-10 分钟
docker compose logs -f    # STATUS 变 healthy 即可用
```

首启由 `docker/entrypoint.sh` 幂等初始化（命名卷 `opc-data` 已初始化则跳过）：建库 ->
`build_kb.py` 摄入官方三域（默认 `--no-extract` 跳过 LLM 抽取以压缩评审等待，`DOCKER_FULL_EXTRACT=1`
取完整本体图谱）-> `reset_demo_data.py` 建演示租户。改端口 `DOCKER_PORT=8080`。
Docker 相关文件集中在 `docker/`，`docker-compose.yml` 与 `.dockerignore` 留仓库根（构建上下文根生效）。
**依赖锁定**：`mcp` 必须 `<2`（2.0 移除 `mcp.server.fastmcp`）；`pyjwt`/`cryptography` 显式声明。

### 7.3 演示数据与环境变量
`scripts/reset_demo_data.py` 一键重建标准演示账号（密码统一 `demo1234`）：`admin`（平台超管）、
`demo1`（旗舰版，3 知识域 + 3 份 PDF + 3 智能体）、`demo2`（标准版）、`demo3`（免费版）；测试脚本依赖 demo1。
`scripts/seed_agent_prompts.py` 幂等填充智能体提示词与欢迎语。`.env.example` 覆盖
LLM/向量/短信/支付/JWT 全部关键配置项；**`.env` 与 `wink.pem` 严禁提交**。
