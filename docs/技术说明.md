# 技术说明：AI课程顾问Agent

## 一、模型与调用方式

- 对话与结构化抽取：火山方舟（OpenAI 兼容接口 `https://ark.cn-beijing.volces.com/api/v3`），对话模型为方舟推理接入点（endpoint id 见运行配置 `data/config/llm.yaml`，portal 可改），function calling 用于工具调用与按 JSON Schema 的知识抽取。
- 向量化：方舟 doubao-embedding-vision（独立接入点，2048 维），密钥经环境变量注入，未写入仓库。
- 重排：默认 LLM 逐条评分策略（可切换为重排模型端点），保证任意环境可用。

## 二、资料分类与知识域体系

知识以**知识域（Domain）**为唯一边界单位，而非按素材 A/B/C 硬分类。系统采用知识域 -> 知识库 -> 文档三级结构：

- **知识域**：语义边界单元。当前设三个知识域：学生课程域（对应素材A，暑期AI素养夏令营）、教师培训域（对应素材B，初高中教师AI素养培训体系 L1-L3）、平台服务域（对应素材C，平台会员/企业合作，资料暂缺）。知识域可自建、可扩展。
- **知识库**：知识域下的文档集合，对应一组本体实体与检索索引。
- **文档**：上传的原始文件（.txt/.docx/.doc/.pdf），经解析、章节切块、向量化与本体抽取后入库。

实体/规则/知识块经 文档->知识库->知识域 链路归属，无 material 列。智能体在 `agents.yaml` 中配置对接的知识域列表，范围外内容不参与该智能体的检索、推荐与计算。资料分类的本质是知识域隔离：学生通道无法检索或计算教师域班型，教师通道无法访问学生域内容，平台域资料缺失时如实回答"无法确认"。

## 三、知识体系：本体（Ontology）+ 检索库

参照 Palantir Foundry 的本体建模范式，知识层由「本体」与「检索库」两部分构成，统一存于单文件 SQLite：

**本体层（语义网络）**
- **对象类型**：知识域、班型/产品、营期、教学地点、师资、费用项、业务规则、知识文档，共 8 类；每类在 `config/ontology_schema.yaml` 中定义属性模式与图元样式，可由 portal 维护。
- **链接类型**：归属、开设于、位于、负责教学、费用构成、受规则约束、优惠适用、是前置（L1->L2->L3 等级链）、同级班型、来源（溯源到文档），共 10 类，均标注方向与基数，双向可读。
- **对象与链接实例**：文档摄入时由 LLM 按 Schema 抽取实体与类型化关系，跨章同名实体深合并；派生链接（归属/溯源/前置链/变体/规则适用）由引擎自动计算，与抽取链接、人工链接三分来源（extracted/derived/manual）。
- **规则对象化**：早鸟、团报、叠加策略、退费阶梯、前置要求、推荐策略均建模为规则对象（参数即数据），由通用规则解释引擎执行，**代码零业务数值**。

**检索库**：sqlite-vec 向量索引 + FTS5（trigram 中文关键词），块级保留文档名与章节用于引用溯源。

## 四、推荐流程

1. 推荐为确定性筛选+生成式理由：本体引擎按约束（城市/日期/线上线下；教师端增加是否连续脱岗、等级）筛选真实班型，再由 LLM 生成逐条对应约束的推荐理由。
2. 推荐策略本身也是库内 `recommend` 规则（声明式 needs/match/日期来源/限额），引擎通用解释。约束不足两个时先追问，确保推荐有据可依。
3. 费用计算为纯确定性：引擎读取产品标准课程费 -> 判断早鸟资格（按缴费日期与早鸟截止日） -> 判断团报人数 -> 按叠加策略（取最高一项）计算最终优惠 -> 加上可选食宿 -> 返回逐项拆解。整个过程不经过 LLM 推理，结果可复现、可审计。

## 五、上下文与异常处理

**上下文管理**：
- SQLite 持久化会话与消息；角色专属 H5 预置身份；重置清空状态与历史。
- 七步业务流程（欢迎分流->身份澄清->约束采集->推荐->详情追问->报名引导->会话控制）由角色提示词约束。会话状态（身份/知识域/当前班型/约束条件）经 set_session_context 工具显式记录并注入每轮系统提示，保证"推荐->追问时间->追问物资"等多轮上下文正确继承。
- 重置操作清空状态与历史，重置后不再引用旧班型。

**异常处理**：
- 空输入：固定模板提示"请输入你想咨询的内容"。
- 超 500 字：固定模板提示"输入内容超过500字,请精简后再发送"。
- 特殊符号：不崩溃，按当前通道角色引导回业务范围。
- 无关问题：说明边界并返回菜单或引导。
- 模型调用失败：统一降级为"模型服务暂时不可用,请稍后重试"。
- 需要人工服务时统一引导"请联系人工课程顾问"，不提供真实联系方式。

## 六、管理工作台（运营后台，平台重点）

管理工作台（`/portal`，账户密码登录，演示账户 `demo`/`demo1234`）是平台的运营中枢，覆盖知识治理、智能体配置、运营分析、质量管理与人机协作全链路，是本平台区别于"只会答题的机器人"的核心。包含七大功能模块：

**1. 知识域管理（知识治理）**
- 知识域 -> 知识库 -> 文档三级结构；知识域可自建、可扩展（可改名称与描述），是问答的唯一边界单位。
- 文档上传支持 .txt/.docx/.doc/.pdf，上传后自动完成解析 -> 章节切块 -> 向量化 -> 本体抽取，全程无需改代码。

**2. 本体知识（可视化本体）**
- 可视化本体图谱：8 类对象（班型/营期/地点/师资/费用项/规则/文档/知识域）与 10 类链接（开设于、位于、是前置、同级班型、优惠适用、来源溯源等）。
- 力导向/放射/聚簇/同心圆/层级/环形/网格多布局，搜索定位、类型筛选、邻域高亮。
- 点击节点查看与编辑属性、确认对象、增删对象间链接；派生链接一键重算；全部变更留有操作记录（可审计）。

**3. 智能体设置（按智能体配置）**
- 按学生/教师/平台三个智能体分别设置：对接的知识域（范围外内容不参与检索/推荐/计算）、对话模型（从"支持的模型"中选）、**能力配置（留资转人工 / 对话质检 开关）**、系统提示词与欢迎词、MCP 接入配置。
- 全部保存即生效（配置热加载，无需重启）。

**4. 数据分析（智能体运营分析）**
- 概览（总会话/总提问/各智能体会话）、近 14 日会话趋势、高频问题 TOP、**未答/边界问题（知识缺口）**、推荐班型分布、各智能体质检分对比。
- 一键生成 **LLM 运营洞察**（分析运营数据给出改进建议）；全部指标可按智能体筛选。

**5. 线索转化（留资工单·人机协作）**
- 智能体在对话中采集的报名意向留资，在此线索转化；工单状态流转（待跟进 -> 已跟进 -> 已转化/无效），可填跟进记录。
- 仅做留资跟进流转，不做报名/支付管理（守住"不做课程业务系统"的边界）。

**6. 会话记录与质检（质量管理）**
- 查看全部会话的状态与逐条消息（含工具调用）。
- **对话质检评分**：LLM 按准确性/规范性/体验三维评分 + 红线问题检测 + 评语，支持单会话质检与批量质检，列表显示质检分（对应赛题"知识准确与对话体验"评分维度的自我度量）。

**7. 系统设置（模型与渠道）**
- 模型及参数：对话服务地址、API Key、支持的模型清单（各智能体可切换）、向量/重排模型与策略、温度、上下文轮次等，保存后热加载。
- **渠道令牌**：为不同渠道（第三方 Agent/合作系统）签发 MCP 接入令牌（`ak_` 前缀），支持启用/禁用/删除、一键复制 MCP 配置；存在有效令牌时 MCP 连接需携带 `Authorization: Bearer` 令牌，无令牌时开放兼容。

## 七、工程架构

FastAPI 单服务同时提供：REST + SSE 真流式（H5 对话与 portal）、三个 MCP streamable HTTP 端点（渠道令牌鉴权，供 OpenClaw/WorkBuddy 等第三方 Agent 接入）、静态前端；核心工具一份实现三处复用（Agent 循环/MCP/REST）。前端 React + Vite：前台三入口移动优先，portal 管理工作台内置 cytoscape 本体图谱与上述七大运营模块。整体 AI 原生：知识抽取、查询改写、重排、运营洞察、对话质检均由 LLM 完成，配置全部文件化、可热更新。

## 八、AI 辅助情况

本项目在 Claude Code 辅助下完成：架构设计与编码由人机协作实现，知识抽取与问答生成为运行时 LLM 能力；所有知识域事实均经自动化回归测试（20 项事实断言 + 25 组验收用例）锁定，未发现编造。AI 辅助范围包括：代码生成与重构、提示词调优、测试用例编写、文档撰写；运行时的知识抽取、查询改写、推荐理由生成、重排评分均由火山方舟豆包模型实时完成。所有业务数值（价格/日期/优惠规则）均存于库内规则记录，由规则引擎确定性执行，AI 不参与数值计算。
